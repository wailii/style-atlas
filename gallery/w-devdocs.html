创建对话补全

给定一段对话，让模型生成下一条回复。支持文本与图片输入、流式输出、工具调用和结构化输出。

POSThttps://api.qiyun.example/v1/chat/completions

认证#

所有请求在 Authorization 头里带上密钥。密钥在控制台「访问密钥」页创建，只在创建时显示一次。

先装 SDK。下面的命令和右侧代码会跟着你选的语言一起切换。


      
不要把密钥写进前端代码或提交到仓库。泄露后在控制台吊销，旧密钥立即失效。

    


    

      
基本调用#

      
最少只需要 model 和 messages 两个字段。messages 按时间顺序排列，最后一条通常是用户的提问。

      
模型会读取全部历史消息，所以多轮对话时，把之前的回复也放回 messages 里再发一次。

      
默认返回完整结果，耗时随输出长度增加。需要边生成边显示，用下面的流式输出。

    


    

      
请求参数#

      
带「子字段」按钮的参数可以展开查看嵌套结构。

      

    


    

      
流式输出#

      
设置 stream: true 后，服务端用 SSE 逐段推送 delta，最后一帧是 [DONE]。每一帧只含新增的片段，客户端自己拼接。

      
首个字符通常在 300 毫秒内到达，长回复的总耗时不变，但用户等待的感觉短很多。

      
流式模式下，用量统计放在最后一帧，需要同时设置 stream_options.include_usage。

    


    

      
工具调用#

      
在 tools 里声明函数。模型认为需要时，返回 tool_calls 而不是文本，参数是符合你给的 JSON Schema 的字符串。

      
你执行函数后，把结果以 role: "tool" 的消息追加到 messages，再请求一次，模型据此给出最终回复。

      
参数由模型生成，可能缺字段或类型不对。执行前先校验。

    


    

      
响应对象#

      
返回一个 chat.completion 对象。

      

    


    

      
错误码#

      
出错时返回非 2xx 状态码和统一的 error 对象。429 和 5xx 可以重试，建议指数退避，间隔从 1 秒起。

      

        
状态码error.code说明

        
400invalid_request参数缺失或类型不对，message 里指出具体字段。

        
401invalid_api_key密钥错误、已吊销或没有带 Authorization 头。

        
402quota_exceeded账户余额或套餐额度用完。

        
429rate_limited超过每分钟请求数或 Token 数，响应头 retry-after 给出等待秒数。

        
500server_error服务端内部错误，可重试。
